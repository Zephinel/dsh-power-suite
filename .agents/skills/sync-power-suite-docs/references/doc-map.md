# Doc map — dsh-power-suite

Paths are repo-root relative. Load this before auditing. A file with mixed classes
is split by section; when a doc is new and not listed here, classify it with the
rules at the bottom before touching it.

What ships: `package.json` `files` publishes `lib/**` (built entries),
`README.md`, `CHANGELOG.md`, `PRODUCT.md`, `docs/**`, `assets/**`, `locale/**`
and `release-notes/**`. `.agents/**`, `test/**` and `src/**` are repo-only, and
`lib/` is a gitignored build output produced by `scripts/build.mjs` (esbuild),
not a checked-in file. There is no vendored tree and no bilingual doc pair.

## Classification rules for a new doc

- Planned/forward-looking markers ("will", "future", "planned", "next", "TODO",
  or the equivalent Chinese terms) with no matching code → **as-planned**: leave
  the intent, flag it if unmarked.
- A dated verification record, decision record, release history, captured-run
  log or archived note → **historical**: append, don't rewrite.
- Describes current behavior, copy, requirements, counts, paths or release state
  → **as-built**: audit it.
- Generated output (`assets/`, `docs/assets/`, raw captures) or legal text →
  **generated/asset/legal**: regenerate or leave.
- A mixed file → split it by section before editing, using the splits listed in
  the tables above.
- Ambiguous → ask the owner; default to leaving it and flagging it.
