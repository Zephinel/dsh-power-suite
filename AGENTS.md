# Repository agent instructions

- **Release / publish work:** load `.agents/skills/release-power-suite/SKILL.md` before changing a version, release notes, tags, or publishing; its pre-tag documentation audit is mandatory. A code/docs/page change is not a release request; preparation and tagging are separate approval gates, and tagging/publishing needs the user's explicit approval for the exact version.
- **No stale or rotted docs:** load `.agents/skills/sync-power-suite-docs/SKILL.md` after behavior, user-visible copy, settings, counts, install steps, environment-version or release-state changes, and when a docs or consistency check fails. A release audits every as-built claim touched since the last tag (prose, counts, versions, screenshots) before tagging; a superseded screenshot or an out-of-date version or count is a defect that blocks the tag unless the owner waives it explicitly.
- Keep `README.md` and `README.zh.md` in sync and portable (no GitHub `> [!` alerts) and `docs/` links valid inside the npm tarball; in `docs/verification.md`, only `## Automated` is live — dated rounds below it are historical evidence.
